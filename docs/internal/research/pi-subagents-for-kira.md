# Pi subagents as a reference for Kira

**Question:** Can Foundry reuse the approach in `gotgenes/pi-packages/packages/pi-subagents` to let Kira spawn agents and show their sessions in the desktop workbench?

**Conclusion:** Yes, the core approach fits: each subagent is a separate in-process Pi `AgentSession`, driven independently from Kira's session. Treat the package as a design reference, not a drop-in UI or an internal library. Foundry's per-chat session ownership, SQLite persistence, and React workbench need an explicit adapter. In particular, do not use the package's unqualified process-global service as Foundry's multi-chat registry.

## What the reference does

The cloned repository is at commit [`69e2b81510a1266cce570730f1bf1a8715a317ad`](https://github.com/gotgenes/pi-packages/tree/69e2b81510a1266cce570730f1bf1a8715a317ad), package version `21.7.6`. Its README describes an in-process core, separate child sessions, and a TUI widget/transcript viewer ([README](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/README.md#L5-L21)). It creates a child session, gives it an independent `SessionManager`, binds extensions, and runs `session.prompt()`; `SubagentSession` owns turn, steer, resume, and dispose behavior ([session factory](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/lifecycle/create-subagent-session.ts#L199-L309), [session wrapper](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/lifecycle/subagent-session.ts#L99-L190)). A manager tracks each run, gates background concurrency, and handles abort/resume ([manager](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/lifecycle/subagent-manager.ts#L201-L350)).

Its live status model comes from subscribing to the child's Pi session events: tool start/end, partial text, turn count, usage, and compaction are projected into agent state ([observer](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/observation/record-observer.ts#L31-L80)). The TUI widget polls that state and uses `ctx.ui.setWidget(..., { placement: "aboveEditor" })` ([widget](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/ui/agent-widget.ts#L55-L84), [render lifecycle](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/ui/agent-widget.ts#L292-L337)). That rendering is Pi-TUI-specific; the observer and lifecycle model are the reusable ideas.

The public `SubagentsService` supports spawn, list/get, abort, steer, and resume. Its snapshots carry final results, metrics, and an `outputFile`, but intentionally omit live activity such as current tools and partial response text ([service contract](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/service/service.ts#L53-L153), [snapshot projection](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/service/service-adapter.ts#L162-L193)). The package writes child transcripts in Pi JSONL format; without a parent session file it falls back to a temp directory ([session path](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/session/session-dir.ts#L23-L40)).

## Fit with Foundry

Foundry already creates a Pi `AgentSession` for each chat through `createAgentSessionServices` and `createAgentSessionFromServices` ([`agent.ts`](../../../apps/desktop/src/main/pi/agent.ts#L94-L156)). The parent sessions use `SessionManager.inMemory()` and override `_persist` to store entries in Foundry's SQLite `ThreadStore`, rather than writing Pi session JSONL files ([`storage.ts`](../../../apps/desktop/src/main/pi/storage.ts#L43-L74)). The Pi version is `^0.85.1`; the reference declares a `@earendil-works/pi-coding-agent >=0.81.0` peer dependency, though its own dev dependencies are `0.84.4` ([reference package metadata](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/package.json#L1-L60)). The session API direction is compatible, but Foundry's exact version should be verified with a build/test before adopting the dependency.

The app keeps a map of open conversations, and disposes an idle conversation when it is left ([`openChats.ts`](../../../apps/desktop/src/main/pi/openChats.ts#L174-L210)). A package manager tied to that parent session will therefore stop its children on parent shutdown, as the reference does. If child work should continue after switching away from an idle chat, Foundry must change that lifetime rule or host those agents outside the chat session.

The renderer already has a typed main-to-renderer event path: `ChatEvent` events carry `threadId`, are pushed over IPC, and are consumed by `App` ([`bridge.ts`](../../../apps/desktop/src/preload/bridge.ts#L338-L383), [`index.ts`](../../../apps/desktop/src/main/index.ts#L138-L142), [`App.tsx`](../../../apps/desktop/src/renderer/src/App.tsx#L346-L375)). Child events should use a separate typed channel or discriminant and include the parent `threadId`; they should not be inserted into Kira's `ChatTranscript`. Foundry's existing `Workbench` is a right-side tabbed pane (Context, Workspace, opened files), while the chat footer already stacks queue/status content above the Composer ([`workbench.tsx`](../../../apps/desktop/src/renderer/src/workbench.tsx#L68-L285), [`App.tsx`](../../../apps/desktop/src/renderer/src/App.tsx#L1473-L1592), [`composer.tsx`](../../../apps/desktop/src/renderer/src/composer.tsx#L163-L190)). A compact active-agent row above the Composer plus an Agents workbench tab for the selected transcript maps cleanly to those seams.

## Integration gaps to resolve before building

1. **Per-chat ownership:** the package publishes `getSubagentsService()` through one `Symbol.for(...)` property on `globalThis` and unconditionally deletes it at session shutdown ([service accessors](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/service/service.ts#L156-L185), [extension wiring](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/index.ts#L189-L229)). Foundry can retain multiple running chats in its `openChats` map. The singleton is not a safe way for the workbench to select a manager by chat; key the manager/read model by parent thread, or adapt the service registry.
2. **Live transcript access:** the public service deliberately withholds live session messages and activity. `outputFile` is useful for a stored transcript, but it cannot provide partial token-stream text. Live display needs a scoped progress subscription/read model built from child `AgentSession` events (the reference's `record-observer.ts` is a small pattern to adapt) or a deliberate extension to the package API.
3. **Persistence:** the reference's child JSONL files do not automatically use Foundry's SQLite-backed parent persistence. Foundry can initially read the child `outputFile`, but durable chat-scoped history would need a Foundry store or a deliberate retention policy for those files.
4. **Child tools/extensions:** Foundry adds `foundryExtension` through an inline `extensionFactories` option when constructing the parent ([`agent.ts`](../../../apps/desktop/src/main/pi/agent.ts#L125-L141)); the reference builds a fresh child resource loader ([`create-subagent-session.ts`](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/lifecycle/create-subagent-session.ts#L231-L278)). Verify explicitly whether Kira's child should get Foundry-only capabilities such as MCP tools, and inject them if required. The reference's `Explore` default names an Anthropic Haiku model, so do not copy that fixed ID as Foundry's default; resolve child models against Foundry's own catalog ([`models.ts`](../../../apps/desktop/src/main/pi/models.ts), [default agents](https://github.com/gotgenes/pi-packages/blob/69e2b81510a1266cce570730f1bf1a8715a317ad/packages/pi-subagents/src/config/default-agents.ts)).

## Recommendation

Use `pi-subagents` as the reference for separate in-process sessions, event-based progress, concurrency, cancellation, and result lifecycle. Do not port its TUI widget or copy the whole package. The smallest Foundry-shaped implementation is a per-thread subagent manager and progress read model at the existing Pi session boundary, with a typed IPC stream to React; borrow/adapt the event observer and lifecycle patterns, and render a concise status above the Composer with a full transcript in an Agents workbench tab. First settle whether background agents should survive switching away from their chat; that determines whether ownership belongs to `Conversation` or an app-level manager.

If substantial source is copied, preserve the package's MIT license and copyright notices (`packages/pi-subagents/LICENSE`); its README identifies the upstream tintinweb project and the gotgenes fork.
